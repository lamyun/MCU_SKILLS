# MCU 优化检查表

改进时序、内存、功耗、启动时间或可靠性时使用本参考。

## 先测量

修改代码前先定义：

- 指标和目标。
- 测量工具。
- 构建配置。
- 硬件版本。
- 输入负载。
- 基线结果和波动范围。

## 时序

- 使用 GPIO 时间戳、trace、cycle counter、逻辑分析仪或 RTOS trace 测量。
- 缩短关闭中断区域。
- 将工作移出 ISR 和高优先级任务。
- 在延迟允许时合并总线事务。
- 避免在关键时序路径中打印日志。
- 必要时用 map 和反汇编确认编译优化影响。

## 内存

- 跟踪 Flash、RAM、heap 和每个任务栈。
- 在压力下使用栈高水位，而不仅是静态估算。
- 评审大型全局变量、缓冲区、查找表和格式化字符串。
- DMA 缓冲区应显式声明，并按最坏流量定大小。
- 长期运行固件避免动态分配，除非已测量并控制碎片。

## 功耗

- 分别测量 boot、active、idle、sleep、deep sleep、shutdown。
- 关闭未使用时钟和外设。
- 将外部器件置于已知低功耗状态。
- 配置 GPIO 状态避免漏电。
- 减少唤醒次数并合并工作。
- 验证唤醒源和恢复顺序。
- 尽可能在断开调试器时测量。

## 启动时间

- 区分硬件电源稳定、bootloader、运行时初始化、驱动初始化、应用就绪。
- 延迟非关键初始化。
- 避免无超时长轮询。
- 高效缓存或验证持久化配置。
- 启动诊断要可见但有边界。

## 可靠性

- 对调试中失败过的假设增加断言或计数器。
- 将修复过的缺陷转换成回归测试。
- 为现场故障保留复位后面包屑。
