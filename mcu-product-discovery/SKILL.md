# MCU 产品发现

默认不预设 MCU 厂商、系列、具体型号、封装、开发板或工具链。从用户输入、受控 board profile 和现有项目文件解析目标；缺失时明确标为待确认，示例平台只能按条件选用。

## 概览

使用本技能在写代码之前先确认“该不该做、为谁做、做哪个版本、为什么这个方案最合适”。输出必须能落到需求、架构、验证和发布证据。

## 工作流

1. 定义问题：用户、场景、当前替代方案、触发频率、失败代价。
2. 做市场对标：列出直接竞品、替代工具、自研方案、人工流程和非 MCU 方案。
3. 拆价值假设：效率、成本、风险降低、合规、体验、售后维护。
4. 选 MVP：只保留能验证核心价值的硬件、固件、云/上位机和生产要素。
5. 评估方案：MCU/模块/传感器/通信/供电/安全/OTA/制造复杂度。
6. 转需求：把产品判断写成可测试需求、验收标准和验证方式。
7. 建立回溯：把竞品结论、方案选择、风险接受和需求 ID 记录到决策日志。

## 必需输出

- 产品一句话定位。
- 用户画像和使用场景。
- 竞品/替代方案矩阵。
- MVP 范围与非目标清单。
- 方案评分表和推荐方案。
- 风险假设与验证实验。
- PRD 到需求 ID 的映射。
- 下一阶段应调用的 skill。

## 评分维度

方案选择时至少按这些维度评分：

| 维度 | 关注点 |
| --- | --- |
| 用户价值 | 是否解决高频、高痛或高风险问题 |
| 技术可行性 | MCU 资源、外设、实时性、功耗、可靠性 |
| 制造可行性 | BOM、校准、测试夹具、量产烧录、返修 |
| 维护可行性 | 日志、故障码、升级、回滚、现场诊断 |
| 合规安全 | 功能安全、网络安全、隐私、认证风险 |
| 交付成本 | 人力、周期、供应链、工具链、测试投入 |

## 路由

- 需要 MCU 选型或系统架构时，调用 `$mcu-requirements-architecture`。
- 需要硬件可行性和 Bring-up 风险时，调用 `$mcu-hardware-bringup`。
- 需要测试策略时，调用 `$mcu-verification-test`。
- 需要安全、合规或认证策略时，调用 `$mcu-safety-security-compliance`。
- 需要发布、量产、OTA 或现场维护闭环时，调用 `$mcu-release-production`。
- 跨阶段治理、阶段门和项目审计，调用 `$mcu-development-lifecycle`。

## 可执行工程门禁

可行性决策将转为板卡或发布承诺时，调用 `$mcu-development-lifecycle` 并读取 `references/executable-engineering-gates.md`。未确认的器件/版本/PDF/HIL 输入必须保留为显式假设；mock 执行不能关闭硬件可行性风险。

## 跑中改进交接

流程执行中出现门禁误通过、可重复故障、反复人工绕行、目录混放或实际工具面与本 Skill 不一致时，调用 `$mcu-continuous-improvement`。项目专有证据保存在 lane 运行目录；只有已复现并有回归保护的通用模式才提升到中央持续改进 Skill。
