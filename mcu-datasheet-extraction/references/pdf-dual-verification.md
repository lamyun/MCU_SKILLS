# PDF 双验证门禁

原理图、芯片手册、参考手册、勘误、封装图等 PDF 的版式会影响工程含义，必须使用本门禁。

## 必须顺序

1. 调用 MCU MCP `prepare_pdf_evidence`，传入 PDF 路径、文档类型和最小但完整的页码范围。
2. 把本地 Poppler 产物作为确定性通道：
   - `pdfinfo` 固化页数和基础元数据。
   - `pdftotext -layout` 提取可检索文字、标号、数值和表格候选。
   - `pdftoppm` 将每个选中页渲染为带哈希的 PNG。
3. 调用 Codex `pdf` skill，目视检查原 PDF 和每个选中页的渲染图。检查符号、引脚号、网络名、连接点、交叉线、表格列、脚注、图例、旋转内容和跨页引用。
4. 对齐两条通道并检查文档内部一致性。Poppler 文本不能证明图形连接关系；视觉检查也不能代替精确数值和可检索文字提取；标题、网络、器件值、注释、图例或不同图纸之间互相冲突时也必须登记为差异。
5. 调用 MCU MCP `record_codex_pdf_review`，记录全部已检查页、观察结果和所有差异。
6. 调用 `inspect_pdf_evidence`。只有 `passed=true`，且源 PDF、文本和页面图哈希均未变化，才能继续使用这些事实。

## 门禁规则

- `pending`、`incomplete`、哈希不一致、缺页或存在未解决差异时，不得把内容作为确定工程事实传给下游。
- 扫描型 PDF 即使没有有效文本层，也只有在视觉通道覆盖全部选中页并记录文本层限制后才可通过。
- 大文档应覆盖回答问题所需的全部页，包括图例、续表、注释和变体表，不能只选看似包含答案的一页。
- PDF 哈希变化后必须重新生成证据包并重新视觉复核。
- 差异不只包括 Poppler 与视觉结果不一致；文档内部冲突，以及与已识别 BOM/PCB 版本冲突时也必须阻断 gate。
- `evidence-manifest.json` 必须随事实包保存，引用时同时记录页码及表/图编号或原理图坐标。

## 原理图专项对齐

每条关键连接至少对齐：位号、引脚号、引脚名、网络名、电源域、NC 标记、连接点/交叉线、页码和跨页连接器。两条通道不一致时必须登记为差异，禁止用推断补齐。
